# Adaptive Core v3 --- Authority Boundaries

**Version:** v3.0.0\
**Status:** Hard boundary contract (fail-closed)

This document defines the **non-negotiable authority boundaries** of
Adaptive Core v3.

If any implementation, integration, or documentation implies broader
authority than listed here, it is incorrect and must be treated as a bug
or a design violation.

------------------------------------------------------------------------

## 1. What Adaptive Core v3 IS

Adaptive Core v3 is:

-   A deterministic, read-only advisory engine
-   An upgrade oracle that produces human-reviewed reports
-   A mailbox validator for structured upgrade proposals
-   A bounded evidence and analysis system that can be replayed

It exists to support **human decisions** and **manual upgrades** only.

------------------------------------------------------------------------

## 2. What Adaptive Core v3 is NOT

Adaptive Core v3 is NOT:

-   A transaction executor
-   A node controller
-   A patch delivery system
-   A governance automation engine
-   A self-upgrading intelligence system
-   A key holder or signing authority
-   A Shield signature verifier or Shield trust-registry authority

------------------------------------------------------------------------

## 3. Hard Prohibitions (Fail-Closed)

Adaptive Core v3 MUST NOT, under any circumstances:

-   Execute transactions or sign transactions
-   Modify wallet or node state
-   Hold private keys, seeds, or signing secrets
-   Auto-apply patches, upgrades, or policy changes
-   Auto-merge upgrade proposals
-   "Guess" missing input data or silently accept malformed inputs
-   Provide hidden authority via implicit defaults

Any path that would violate these boundaries MUST fail-closed with
explicit reason IDs.

------------------------------------------------------------------------

## 4. Allowed Outputs

Adaptive Core v3 MAY output:

-   Deterministic findings
-   Deterministic reports (canonical JSON + Markdown)
-   Deterministic integrity envelope (`report_hash` plus local
    `classical_signature` and `pqc_signature` status metadata)
-   Deterministic node summaries (privacy-preserving aggregation)
-   Structured upgrade proposals (generated by external systems,
    validated here)

All outputs are advisory artifacts only.

------------------------------------------------------------------------

## 5. Governance Model: Human Review Only

Adaptive Core supports a structured proposals mailbox at repository root
`proposals/`.

Rules:

-   Proposals MUST conform to the v3 schema:
    `proposals/schema/upgrade_proposal_v3.schema.json`
-   Proposals are submitted via Pull Request only.
-   Proposals require explicit human review and approval.
-   Adaptive Core never applies changes automatically.

Adaptive Core is **mailbox + validator + reporter**, not an executor.

------------------------------------------------------------------------

## 6. Integration Boundary (External Systems)

External systems such as AdamantineOS may:

-   Submit observations to Adaptive Core
-   Consume advisory outputs
-   Generate upgrade proposals based on findings
-   Submit proposals for human review

Adaptive Core never pushes updates outward.

AdamantineOS independently verifies Shield evidence, applies verifier-controlled policy, and remains the authoritative, fail-closed final policy and execution boundary. Adaptive output cannot approve, override, downgrade, bypass, or rescue its result.

------------------------------------------------------------------------

## 7. Shield v4 Cryptographic Separation

Adaptive Core does not parse or verify Shield signature bundles and has no Shield key role, trust registry, signature backend, or OQS dependency.

The Shield verifier-required policy is `classical-ed25519 + ml-dsa`. Optional `fn-dsa` evidence uses Falcon-1024 under `fips206-draft-falcon1024-v1`; it cannot replace or rescue failed required evidence and is not final FIPS 206 proof. Adaptive telemetry cannot change that policy.

Q-ID identity keys and Shield decision-evidence keys remain separate. Cryptographic evidence proves Shield evidence; it does not grant execution authority.

------------------------------------------------------------------------

## 8. Security Posture

These boundaries enforce:

-   Minimal authority surface
-   No hidden escalation paths
-   Auditability of decisions
-   Deterministic replayability
-   No silent mutation

Any violation is a severity-1 design defect.
